# Подробное объяснение проекта ML2

## Кратко о сути проекта

Цель проекта — по данным объявлений о жилье предсказывать цену аренды. Для этого требовалось очистить данные, преобразовать удобства и характеристики жилья в числовые признаки, разделить данные на обучающую и тестовую выборки, обучить и сравнить линейную регрессию, Ridge, Lasso и ElasticNet, подобрать параметр alpha для регуляризованных моделей и оценить качество предсказаний метриками.

## Что решает проект

Проект предсказывает цену аренды объявления (price) по 22 признакам: 20 наиболее частым удобствам жилья, а также числу ванных комнат (bathrooms) и спален (bedrooms). Для сравнения реализованы собственные модели на стохастическом градиентном спуске и модели из sklearn.

Ноутбук идёт по порядку: формулирует теорию, загружает и подготавливает данные, обучает модели, сравнивает метрики, проверяет нормализацию, добавляет полиномиальные признаки и сравнивает модели с наивными прогнозами.

## 1. Теория и обозначения

Пусть X — матрица признаков, а y — вектор фактических цен. В матрицу добавляется столбец единиц, чтобы свободный член тоже вошёл в вектор параметров θ.

Аналитическое решение метода наименьших квадратов записано так:

θ̂ = (XᵀX)⁻¹Xᵀy

Оно минимизирует сумму квадратов ошибок. Если XᵀX нельзя обратить, используют псевдообратную матрицу: θ̂ = X⁺y.

Для Ridge к функции потерь добавляется штраф L2, который сдерживает величину весов. Для Lasso добавляется штраф L1. Он может занулять малые коэффициенты, поэтому Lasso помогает отбирать признаки. ElasticNet сочетает L1 и L2.

Линейные модели можно применять и к нелинейным зависимостям: сначала преобразовать признаки, например добавить степени x², x³ и их произведения. Модель остаётся линейной по коэффициентам, хотя признаки уже нелинейны относительно исходных данных.

Качество объясняется коэффициентом детерминации:

R² = 1 − Σ(yᵢ − ŷᵢ)² / Σ(yᵢ − ȳ)²

Значение 1 соответствует идеальному прогнозу, 0 — прогнозу средним значением цели, отрицательное значение — результату хуже среднего.

## 3. Очистка списка удобств и формирование выборок

В колонке features записаны списки характеристик квартиры. Функция parse_features приводит их к единому виду:

1. Если значение уже является списком Python, функция обрабатывает каждый его элемент.
2. Если значение пустое, возвращается пустой список.
3. Иначе ast.literal_eval пытается безопасно прочитать строку как список.
4. Если это не удаётся, запасной вариант удаляет квадратные скобки, кавычки и пробелы, а затем делит строку по запятым.
5. Пустые элементы отбрасываются.

В результате Hardwood Floors превращается в HardwoodFloors, а Cats Allowed — в CatsAllowed. Это нужно, чтобы одно и то же удобство не учитывалось под разными написаниями.

feature_lists_all применяет эту функцию ко всем строкам исходного набора. Затем из price берутся 1-й и 99-й процентили. Строки без цены и цены за этими границами удаляются. Такой фильтр повторяет предварительную обработку предыдущего проекта; после него остаётся 48 379 объявлений. В ноутбуке пороги вычисляются до разделения на train и test, чтобы сохранить прежнюю схему подготовки данных. Это означает, что test-цены участвуют в выборе порогов; при построении производственного решения границы следует рассчитывать только по train.

После фильтрации данные делятся на обучение и тест в пропорции 75/25. random_state=21 делает разбиение воспроизводимым: при повторном запуске записи попадают в те же части.

Частоты удобств считаются только по train_idx. Counter считает, сколько раз встретилось каждое значение. most_common(20) выбирает 20 наиболее частых значений и одновременно формирует имена будущих признаков. В этом запуске найдено 1 277 уникальных удобств. Список и количества выводятся для проверки.

В данном запуске размеры частей — 36 284 строки для train и 12 095 для test.

## 5. Собственная линейная регрессия и SGD

Класс SGDRegressorCustom реализует линейную регрессию и три варианта штрафа: Ridge (l2), Lasso (l1) и ElasticNet (elasticnet).

### Параметры класса

- penalty выбирает вид регуляризации;
- alpha задаёт её силу;
- l1_ratio задаёт долю L1 в ElasticNet;
- learning_rate — начальный шаг градиентного спуска;
- epochs — число проходов по данным;
- batch_size — число объектов в одном мини-батче;
- random_state — начальное состояние генератора случайных чисел.

### Метод fit

1. np.asarray(..., dtype=float) переводит признаки и цель в численные массивы.
2. Для каждого признака вычисляются среднее и стандартное отклонение. Признаки стандартизуются; нулевые масштабы заменяются на 1, чтобы не делить на ноль.
3. Цена также центрируется и делится на её стандартное отклонение. Это помогает градиентному спуску работать с ценами в тысячах.
4. Веса и свободный член начинают с нуля.
5. default_rng(random_state) создаёт воспроизводимый генератор. На каждой эпохе он перемешивает индексы одним и тем же способом при одинаковых настройках.
6. Индексы проходятся блоками по batch_size. Для блока считается ошибка Xw + b − y и градиент среднего квадратичного отклонения.
7. Для Lasso к градиенту добавляется производная L1-штрафа. Для Ridge добавляется L2-штраф. Для ElasticNet добавляются оба с долями l1_ratio и 1 − l1_ratio.
8. Веса и свободный член обновляются в направлении, уменьшающем ошибку. Шаг обучения постепенно уменьшается с номером эпохи.
9. fit возвращает сам объект, чтобы обучение можно было вызывать цепочкой с созданием модели.

### Метод predict

Новые данные стандартизуются теми средними и масштабами, которые были сохранены при обучении. Затем вычисляется линейный прогноз. В конце преобразование цели отменяется, поэтому прогноз снова выражен в исходных единицах цены.

Этот порядок важен: параметры стандартизации из test не пересчитываются.

### Метрики и сохранение результатов

regression_metrics возвращает три значения:

- MAE — среднее абсолютное отклонение прогноза от цены;
- RMSE — корень из средней квадратичной ошибки, сильнее реагирует на крупные ошибки;
- R² — доля вариации цели, объяснённая моделью.

Для R² в ноутбуке реализована отдельная функция r2_custom: она сама считает суммы квадратов остатков и отклонений от среднего, затем применяет формулу из теоретической части. Для константной цели предусмотрена защита от деления на ноль.

add_result вызывает predict отдельно для train и test, считает метрики и добавляет записи в словари results. Позже из них строятся три таблицы с одинаковыми строками моделей и столбцами train и test.

Собственные четыре модели отличаются только настройками штрафа. Все используют один и тот же seed, поэтому результат SGD воспроизводим.

## 7. Собственные реализации нормализации

MinMaxScalerCustom.fit запоминает минимум и диапазон каждого столбца. transform применяет формулу:

x′ = (x − x_min) / (x_max − x_min)

Если диапазон равен нулю, вместо него используется 1. Поэтому постоянный признак не вызывает деления на ноль.

StandardScalerCustom.fit сохраняет среднее и стандартное отклонение. transform вычисляет:

x′ = (x − μ) / σ

Этот вариант переводит признак к среднему 0 и стандартному отклонению 1. У него также предусмотрена защита для признаков с нулевым отклонением.

fit_transform объединяет обучение скейлера и преобразование обучающих данных. В словаре normalizers рядом находятся собственная реализация и соответствующая версия sklearn. Цикл сравнивает их преобразованные train-матрицы и сохраняет максимальную абсолютную разницу в scaler_checks. В выполненном ноутбуке различие MinMax составило примерно 5.6 × 10⁻¹⁷, Standard — 0: реализации совпали с sklearn с точностью вычислений.

Нормализация особенно полезна градиентным алгоритмам, расстояниям и регуляризованным линейным моделям: признаки с большими числовыми масштабами иначе могут доминировать. Для деревьев решений она обычно не нужна. Для обычной линейной регрессии без штрафа масштабирование не меняет выразительную способность модели, хотя может улучшить численную устойчивость.

## 8. Обучение на нормализованных признаках

Для каждого скейлера обучающая матрица сначала получает параметры преобразования, затем этими же параметрами преобразуется тестовая матрица. Так избегается утечка статистик test в обучение.

На каждой версии данных повторно обучаются все четыре модели sklearn и все четыре собственные модели. Каждая пара результатов добавляется в те же таблицы с суффиксом MinMax или Standard. В конце выводятся обновлённые MAE, RMSE и R².

Нормализация влияет на регуляризацию, потому что меняется масштаб коэффициентов. Поэтому Ridge, Lasso и ElasticNet могут давать отличающиеся результаты после преобразования. Для модели без регуляризации прогнозы обычно остаются почти такими же.

## 9. Полиномиальная регрессия и подбор alpha

Для этого опыта берутся только bathrooms и bedrooms, как требует задание. PolynomialFeatures(degree=10) создаёт степени признаков и их комбинации до десятой степени. include_bias=False не добавляет ещё один столбец единиц, поскольку модели сами оценивают свободный член.

Полученная матрица очень разномасштабна, поэтому к ней применяется StandardScaler. Для выбора параметров обучающая часть дополнительно делится на fit и validation. Скейлер сначала обучается только на fit, а validation преобразуется его параметрами.

Для Ridge, Lasso и ElasticNet проверяются alpha 100, 1 000 и 10 000. Для каждого кандидата рассчитывается validation RMSE. groupby('model') и idxmin() выбирают лучший alpha отдельно для каждого вида регуляризации.

После подбора модели заново обучаются на всей основной train-части и оцениваются на test. Это исключает использование test при выборе alpha. Полиномиальные модели добавляются в те же таблицы метрик.

Помимо sklearn-моделей на полиномиальных признаках запускаются собственные SGD-версии линейной регрессии, Ridge, Lasso и ElasticNet. Они используют найденные alpha. Для этой матрицы задан меньший шаг обучения, потому что полиномиальные признаки сильнее коррелируют и могут иметь более сложный масштаб.

Сравнение train/test показывает переобучение: например, у полиномиальной линейной sklearn-модели RMSE составляет 1 074.245 на train и 7 781.849 на test. Регуляризация снижает тестовую ошибку: лучшая из выбранных sklearn полиномиальных моделей — Lasso с alpha=100, её test RMSE около 1 132.655. Здесь видно, что полином высокой степени сам по себе не гарантирует хорошее обобщение.

## Как правильно прочитать формулы вслух

Знак транспонирования T означает «транспонированная матрица», степень −1 — «обратная матрица», а знак шляпки над буквой — оценённое значение. Греческие буквы: θ читается «тета», λ — «лямбда», μ — «мю», σ — «сигма».

### Аналитическое решение линейной регрессии

Формула: θ̂ = (XᵀX)⁻¹Xᵀy.

Читается так: «Тета с крышкой равна обратной матрице произведения X транспонированной на X, умноженной на X транспонированную и на вектор y».

Проще по смыслу: сначала строим матрицу X транспонированная на X, обращаем её, затем умножаем на X транспонированную и на целевые значения y. Результат — найденные коэффициенты модели.

### Общая функция потерь с регуляризацией

Формула: min по θ от суммы по i от 1 до N функции потерь L от f(xᵢ, θ) и yᵢ, плюс λR(θ).

Читается так: «Найти такие параметры тета, чтобы сумма ошибок модели на всех объектах плюс лямбда, умноженная на штраф за параметры, была минимальной».

Здесь min означает минимизацию, N — число объектов, f — прогноз модели, L — ошибка на одном объекте, R — штраф за сложность или величину коэффициентов. λ управляет силой штрафа.

### Регуляризация L1

Формула: ||θ||₁ = сумма по i от 1 до d абсолютного значения θᵢ.

Читается так: «Норма тета один равна сумме абсолютных значений коэффициентов тета от первого до d-го».

Две вертикальные черты с индексом 1 означают L1-норму, а вертикальные черты вокруг одного коэффициента — его абсолютное значение. Чем больше ненулевых или крупных коэффициентов, тем больше штраф.

### Ridge

Формула: θ̂ = (XᵀX + λI)⁻¹Xᵀy.

Читается так: «Тета с крышкой равна обратной матрице: X транспонированная на X плюс лямбда, умноженная на единичную матрицу I; всё это умножается на X транспонированную и y».

Добавка λI стабилизирует матрицу и уменьшает коэффициенты. I — единичная матрица подходящего размера.

### Коэффициент R²

Формула: R² = 1 − сумма квадратов разностей между yᵢ и прогнозом ŷᵢ, делённая на сумму квадратов разностей между yᵢ и средним значением y.

Читается так: «Эр в квадрате равен единице минус сумма квадратов ошибок, делённая на общую сумму квадратов отклонений цели от её среднего».

Числитель — ошибка модели. Знаменатель — ошибка простого прогноза средним. Поэтому коэффициент сравнивает модель с этим простым базовым прогнозом.

### MinMaxScaler

Формула: x′ = (x − x_min) / (x_max − x_min).

Читается так: «Икс с штрихом равен икс минус минимальное значение, делённое на разность максимального и минимального значений».

После преобразования значения обычно попадают в диапазон от 0 до 1.

### StandardScaler

Формула: x′ = (x − μ) / σ.

Читается так: «Икс с штрихом равен икс минус среднее мю, делённое на стандартное отклонение сигма».

В результате признак центрируется около нуля и измеряется в единицах своего стандартного отклонения.

## Термины из подбора alpha простыми словами

В ноутбуке есть фраза: «Для Ridge, Lasso и ElasticNet проверяются alpha 100, 1 000 и 10 000». Её смысл такой: обучаются три вида регуляризованной модели, и для каждого вида по очереди пробуются три значения силы штрафа. Затем выбирается настройка с наименьшей ошибкой на validation-части.

### Что такое Ridge

Ridge — линейная регрессия со штрафом L2. К обычной ошибке модели добавляется сумма квадратов коэффициентов:

Функция потерь = ошибка модели + alpha × сумма квадратов весов.

Если alpha увеличить, крупные веса сильнее уменьшаются. Обычно они становятся ближе к нулю, но редко становятся ровно нулевыми. Это помогает модели не подстраиваться слишком точно под обучающие примеры.

Название «гребневая регрессия» — перевод слова Ridge. В коде она создаётся как SkRidge.

### Что такое Lasso

Lasso — линейная регрессия со штрафом L1. К ошибке добавляется сумма абсолютных значений коэффициентов:

Функция потерь = ошибка модели + alpha × сумма абсолютных весов.

При достаточно сильном штрафе некоторые коэффициенты становятся ровно нулевыми. Значит, модель фактически перестаёт использовать соответствующие признаки. Поэтому Lasso не только ограничивает веса, но и может выполнять отбор признаков.

В коде sklearn-модель называется SkLasso, собственная версия использует penalty='l1'.

### Что такое ElasticNet

ElasticNet объединяет штрафы L1 и L2:

Функция потерь = ошибка модели + alpha × l1_ratio × сумму абсолютных весов + alpha × (1 − l1_ratio) × половину суммы квадратов весов.

В проекте для полиномиальной модели l1_ratio=0.5: обе части штрафа имеют одинаковую долю. ElasticNet сочетает свойство Lasso занулять часть весов и свойство Ridge плавно уменьшать остальные. В коде sklearn-модель создаётся как SkElasticNet.

### Что означает alpha

Alpha читается «альфа». Это гиперпараметр — настройка модели, которую выбирают до окончательной оценки. Alpha не является ни целевой переменной, ни одним из весов модели.

- Малое alpha означает слабый штраф. Модель ближе к обычной линейной регрессии и может сильнее переобучиться.
- Большое alpha означает сильный штраф. Коэффициенты уменьшаются; если штраф чрезмерный, модель может стать слишком простой и недообучиться.
- При alpha=0 регуляризационный штраф отсутствует.

Значение alpha действует по-разному в Ridge, Lasso и ElasticNet, потому что у них разные формулы штрафа. Кроме того, его подходящий масштаб зависит от масштаба признаков и от формулировки функции потерь. Поэтому выбранные для полиномиальных признаков значения нельзя напрямую считать «сильнее» или «слабее» параметров базовых моделей без учёта этих различий.

### Зачем проверяются несколько значений

Полиномиальные признаки степени 10 делают модель гибкой: она может описывать сложные формы, но легче подстраивается под случайные особенности train. Регуляризация ограничивает эту гибкость. Заранее нельзя знать, какой штраф даст лучший баланс, поэтому в ноутбуке перебираются значения alpha:

- 100;
- 1 000;
- 10 000.

Это небольшой набор кандидатов, называемый сеткой гиперпараметров.

### Что такое fit, validation и test

- Fit-часть — данные, на которых конкретная модель подбирает свои коэффициенты.
- Validation-часть — отдельная часть обучающей выборки. Она нужна, чтобы сравнить варианты alpha и выбрать лучший. Коэффициенты на ней не обучаются.
- Test-часть — данные для финальной проверки уже выбранного варианта. Её не используют при выборе alpha, чтобы оценка качества оставалась независимой.

В коде обучающая часть временно разделяется на fit и validation. Для каждого сочетания «вид модели + alpha» считается validation RMSE. Строка с минимальным RMSE для Ridge выбирает свой alpha; то же отдельно делается для Lasso и ElasticNet. В выполненном ноутбуке validation выбрала alpha=100 для Lasso, alpha=1 000 для ElasticNet и alpha=10 000 для Ridge.

После выбора alpha модель заново обучается на всей основной train-выборке. И только после этого её качество вычисляется на test. Иными словами, фраза «Ridge, Lasso и ElasticNet проверяются alpha» означает: «Для каждой из трёх моделей подбирается сила регуляризации alpha по ошибке на validation-данных».

## Класс SGDRegressorCustom — параметры и обучение

Строка class SGDRegressorCustom: объявляет собственный класс модели. __init__ сохраняет настройки в объекте:

- penalty=None означает обычную линейную регрессию без штрафа.
- penalty='l2' включает Ridge-подобный штраф.
- penalty='l1' включает Lasso-подобный штраф.
- penalty='elasticnet' включает оба штрафа.
- alpha — сила регуляризации; чем она больше, тем сильнее штраф.
- l1_ratio управляет долей L1 в ElasticNet.
- random_state делает порядок перемешивания воспроизводимым.

В начале fit входы превращаются в массивы вещественных чисел. Затем self.mean_ и self.scale_ сохраняют среднее и стандартное отклонение каждого признака. Масштабирование проводится здесь, чтобы градиентный спуск не делал чрезмерно большие шаги по признакам с большим диапазоном.

Строка self.scale_[self.scale_ == 0] = 1.0 защищает постоянные признаки от деления на ноль. После этого values центрируется и масштабируется.

Цель тоже преобразуется: target становится отклонением от среднего в единицах стандартного отклонения цены. Поэтому оптимизатор работает с числами порядка единицы, а не с тысячами долларов. self.target_mean_ и self.target_scale_ сохраняют параметры обратного преобразования.

self.coef_ — вектор весов по одному на каждый входной признак. self.intercept_ — свободный член. Начальные нули означают, что оптимизатор стартует с простой нейтральной точки.

rng.permutation(n) выдаёт случайный порядок всех обучающих строк. Цикл epoch повторяет обучение заданное число раз. Внутри каждой эпохи rate уменьшается по формуле learning_rate / (1 + epoch * 0.02): поздние обновления становятся осторожнее и меньше колеблются около минимума.

Внутренний цикл берёт участки индексов размером batch_size. xb — признаки текущего мини-батча, yb — соответствующие цены. Выражение xb @ self.coef_ + self.intercept_ рассчитывает прогнозы, а error хранит разницу «прогноз минус факт».

xb.T @ error / len(batch) — градиент средней квадратичной ошибки по весам. Деление на размер блока превращает сумму градиентов в среднее, поэтому величина шага меньше зависит от размера мини-батча.

Для L1 используется sign(coef): знак задаёт направление штрафа. Для L2 градиент пропорционален самому коэффициенту, поэтому крупные веса сильнее тянутся к нулю. У ElasticNet оба вклада складываются; l1_ratio задаёт долю L1, а 1 − l1_ratio — долю L2. Штраф применяется к весам, но не к intercept.

self.coef_ -= rate * grad делает шаг против градиента. self.intercept_ обновляется по среднему отклонению блока; свободный член не регуляризуется. return self завершает fit и возвращает обученную модель.

## Прогноз и метрики

В predict признаки преобразуются ровно теми средними и масштабами, которые были сохранены в fit. Модель делает матричное умножение и прибавляет свободный член. Затем прогноз переводится обратно в доллары: умножается на стандартное отклонение цели и сдвигается на её среднее.

В r2_custom:
- actual и predicted приводятся к численным массивам;
- residual_sum — сумма квадратов ошибок модели;
- total_sum — сумма квадратов отклонений реальных цен от их среднего;
- 1 − residual_sum / total_sum вычисляет R²;
- если цель константна и total_sum равна нулю, отдельная ветка не допускает деления на ноль.

regression_metrics объединяет три метрики в словарь. MAE и RMSE вызывают готовые функции sklearn, а R² берётся из собственной r2_custom.

add_result вызывает predict дважды: один раз на train и один на test. Затем метрики считаются независимо. В каждой таблице добавляется строка с именем модели и парами значений train/test. Так проще заметить переобучение: хорошая train-метрика при заметно худшей test-метрике обычно указывает, что модель плохо обобщает.

## Сопоставление с библиотечными моделями

sklearn_specs — список пар «подпись модели — объект». Цикл последовательно обучает каждую модель на X_train, y_train. Словарь sklearn_models сохраняет обученные модели, а add_result добавляет их измерения в общие списки.

Затем для каждого названия метрики создаётся DataFrame. set_index('model') переносит названия моделей в индекс строк. round(3) округляет вывод до трёх знаков, чтобы таблицы было проще читать.

Важно: качество оценивается на том же test-разбиении, что и собственные алгоритмы. Поэтому сравнение корректно: различается реализация модели, но не тестовые объявления.

## Скейлеры — что делает каждая строка

В MinMaxScalerCustom.fit минимум и максимум вычисляются отдельно по каждому столбцу. range_ — разность максимума и минимума. Нулевой диапазон заменяется единицей.

transform использует сохранённые минимум и диапазон, а не пересчитывает их для новых данных. fit_transform сначала вызывает fit, затем transform.

В StandardScalerCustom.fit запоминаются среднее и стандартное отклонение каждого столбца. transform вычитает среднее и делит на стандартное отклонение. Та же защита меняет нулевой масштаб на 1.

Словарь normalizers хранит пары: собственный класс и соответствующий sklearn-класс. Цикл обучает каждый из них на X_train, преобразует train и вычисляет максимальную абсолютную разницу между матрицами. Результат около нуля означает, что собственная реализация совпадает с библиотечной с точностью вычислений.

В следующем цикле модели снова создаются заново. type(model)(**model.get_params()) копирует тип модели и её настройки, но не старые обученные веса. Скейлер fit только на train; transform на test использует уже сохранённые параметры. Потом модели sklearn и собственные модели обучаются на преобразованной train-матрице.

## Полиномиальные признаки — подробный ход выбора alpha

base_train и base_test оставляют только bathrooms и bedrooms. Это важное ограничение: удобства в этом эксперименте не используются.

PolynomialFeatures степени 10 добавляет квадраты, кубы, смешанные произведения и другие сочетания этих двух признаков. include_bias=False отключает столбец констант, поскольку LinearRegression, Ridge, Lasso и ElasticNet имеют собственный intercept.

Далее train разбивается ещё раз на poly_fit и poly_val. Это не заменяет основной test: validation нужна только для настройки alpha, test остаётся финальной независимой оценкой.

poly_scaler сначала обучается на poly_fit. Трансформированные poly_val сравниваются с моделями, которые обучались только на poly_fit. После выбора alpha scaler повторно обучается на всей основной train-части; затем тем же scaler преобразуется основной test. Два этапа fit не используют test: сначала нужна честная validation-оценка, затем — финальное обучение на большем объёме данных.

alpha_grid — список проверяемых значений. Цикл создаёт три регуляризованные модели для каждого alpha. После fit прогноз на validation сравнивается с y_val; корень средней квадратичной ошибки сохраняется как validation_RMSE.

selection превращает список результатов в таблицу. groupby('model') разбивает её по типу регуляризации. idxmin() находит индекс строки с минимальным validation_RMSE для каждого типа. best_rows поэтому содержит по одной лучшей настройке для Ridge, Lasso и ElasticNet.

Следующий цикл заново создаёт модели с найденными значениями и обучает их уже на полной train-части. В poly_models также помещается обычная полиномиальная LinearRegression для базового сравнения.

Затем запускаются собственные SGD-модели на тех же полиномиальных матрицах. Для каждой регуляризованной версии используется alpha, найденная для соответствующего sklearn-вида. Шаг обучения уменьшен до 0.0001, а число эпох увеличено до 100, поскольку полиномиальные признаки сильнее коррелируют. add_result сравнивает их train/test метрики с остальными моделями.

## Наивные модели и финальная логика выбора

Для Baseline mean создаётся объект, который всегда возвращает среднее y_train. Для Baseline median — объект, который возвращает медиану y_train. lambda сохраняет конкретное value для каждой модели. Оба объекта имеют метод predict, поэтому add_result может обработать их так же, как обычные регрессоры.

final_test объединяет тестовые MAE, RMSE и R² в одну таблицу. idxmin() выбирает модель с наименьшим test RMSE.

Для оценки стабильности из сравнения исключаются только константные baseline-модели. Затем для каждой обучаемой модели берётся абсолютная разница между test RMSE и train RMSE. Минимальный разрыв считается наибольшей стабильностью по этому критерию. Это именно принятое в ноутбуке определение стабильности; оно не означает, что модель с минимальным разрывом обязательно имеет самую маленькую test-ошибку.

# Вопросы, которые могут задать на защите

### Почему задача является регрессией?

Потому что модель предсказывает числовую величину — цену аренды. Цена может принимать разные численные значения, и ошибка измеряется разницей между предсказанным и фактическим значениями.

### Почему price нельзя включать в X?

Price — ответ, который модель должна предсказать. Если передать её среди входных признаков, модель увидит правильный ответ во время обучения. Это утечка целевой переменной, и оценка качества станет бессмысленной.

### Зачем нужны train и test?

На train модель изучает коэффициенты. На test проверяется, как она работает на объектах, которые не участвовали в обучении. Только test-метрика даёт оценку способности обобщать закономерность.

### Почему частоты удобств считаются на train?

Чтобы тестовая выборка не влияла на выбор входных признаков. В реальной ситуации будущие объявления заранее неизвестны, поэтому статистики признаков следует строить по доступным обучающим данным.

### Почему выбран именно набор из 20 удобств?

Это требование задания. Частые признаки создают информативные бинарные столбцы, но ограничивают размер матрицы и число очень редких характеристик.

### Почему заполнять пропуски медианой?

Регрессору нужны числовые значения. Медиана устойчива к редким экстремальным значениям и сохраняет типичное значение признака. Она вычислена только на train, чтобы test не влиял на подготовку.

### Почему зафиксирован random_state?

Разбиение и порядок мини-батчей содержат случайность. Фиксированный seed позволяет получить те же выборки и воспроизвести результат при повторном запуске.

### В чём отличие batch, mini-batch и stochastic gradient descent?

Batch gradient descent считает градиент по всей выборке за одно обновление. SGD в узком смысле обновляет веса по одному объекту. Mini-batch использует небольшой блок примеров за обновление. В данном коде размер блока — 512, то есть фактически реализован mini-batch SGD.

### Что означает intercept?

Intercept — свободный член b в формуле прогноза ŷ = Xw + b. Это базовый сдвиг прогноза, когда признаки находятся на нулевом уровне. Веса показывают вклад признаков относительно этого сдвига.

### Зачем масштабировать X и y внутри собственной SGD-модели?

Если признаки имеют сильно разные масштабы, градиент может делать неравномерные шаги и сходиться медленно. Масштабирование цели тоже помогает: оптимизатор работает с числами около единицы. В predict оба преобразования отменяются, чтобы прогноз возвращался к исходным долларам.

### Что такое переобучение в этом эксперименте?

Полиномиальная модель степени 10 имеет много степенных комбинаций и может слишком точно подстроиться под train. Если ошибка на train мала, а на test существенно выше, модель запомнила особенности обучающих объектов, которые не повторяются в новых данных. Регуляризация уменьшает веса и может сократить этот разрыв.

### Почему alpha подбирается на validation, а не на test?

Если выбирать alpha по test, информация о тестовых ответах начнёт влиять на настройку модели. Тогда test перестанет быть независимой проверкой. Validation предназначена для выбора настроек, test — только для финальной оценки.

### Почему лучшая по RMSE модель может не быть лучшей по MAE?

RMSE возводит ошибки в квадрат и сильнее реагирует на большие промахи. MAE усредняет абсолютные ошибки линейно. Поэтому одна модель может иметь меньше типичную ошибку, а другая — меньше крупных промахов.

### Что показывают результаты именно этого запуска?

Лучший test RMSE в итоговой таблице у Custom Lasso SGD. Наиболее стабильной по абсолютному разрыву train/test RMSE стала Sklearn ElasticNet + Standard. Основной test R² около 0.577 — выше порога 0.4 из чек-листа. Значения метрик измеряются в единицах цены, то есть долларах в используемом датасете.

### Почему цифры не обязаны точно совпасть с примером чек-листа?

В чек-листе примерные метрики могут отличаться в зависимости от версии sklearn и конкретного разбиения. Здесь используется random_state=21 и фильтр 1-го/99-го процентилей из предыдущего проекта. Сначала стоит сверить порядок данных и разбиения, а затем сравнивать близость метрик и обязательный порог R².
